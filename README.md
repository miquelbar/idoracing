# ACC Coach 🏎️

[![CI](https://github.com/miquelbar/acc-coach/actions/workflows/ci.yml/badge.svg)](https://github.com/miquelbar/acc-coach/actions/workflows/ci.yml)
[![License: MIT](https://img.shields.io/badge/License-MIT-blue.svg)](LICENSE)
[![Python: 3.11+](https://img.shields.io/badge/python-3.11+-blue.svg)](https://www.python.org/)

**ACC Coach** is a local, privacy-respecting telemetry analysis and driving coach for **Assetto Corsa Competizione (ACC)**. It is designed to run natively on Linux (especially Arch Linux) and via Docker, providing grounded, reproducible telemetry insights and local AI-assisted driver coaching.

The initial development focuses on the **Porsche 911 GT3 R (992)** at the **Circuit Ricardo Tormo (Valencia)**.

---

## 🎯 Key Features

1. **MoTeC & CSV Telemetry Import**: Direct binary parsing of native MoTeC `.ld` telemetry logs and `.ldx` XML lap markers generated by ACC, plus support for tabular CSV exports.
2. **Deterministic Distance Alignment**: Interpolates telemetry channels onto a uniform spatial grid along the track distance ($s$), decoupling analysis from erratic sampling frequencies.
3. **Cumulative Delta Time ($\Delta t(s)$)**: Continuous mathematical calculation of time gained and lost throughout the lap.
4. **Corner Breakdown & Technique Diagnostics**:
   - Apex minimum speed comparison ($\Delta V_{min}$).
   - Braking point identification and distance delta (meters early/late).
   - Throttle pick-up and re-acceleration detection.
   - Grounded diagnoses (e.g., overslowing at apex, hesitant throttle on exit, over-downshifting).
5. **Local AI Coach with Ollama**:
   - Connects to your locally hosted Ollama instance (e.g., `qwen3:14b`, `qwen3.8:27b-32k`).
   - Grounded strictly in verified numerical telemetry metrics (zero hallucinations).
   - Structured reports: Observed facts, supporting metrics, driving hypotheses, targeted track exercises, verification indicators, and confidence ratings.
   - **Full offline fallback**: Runs a deterministic analytical rule engine if Ollama is disabled or unreachable.
6. **Zero Cloud Leaks**: Telemetry never leaves your local machine. No external APIs or telemetry collection.
7. **Interactive Dashboard**: Multi-row synchronized Plotly telemetry charts (Speed, $\Delta t$, Throttle, Brake, Gear) and session history powered by Streamlit and SQLite.

## 🏗️ Architecture

```
acc-coach/
├── domain/             # Pydantic v2 data models (Session, Lap, LapComparison, CoachReport)
├── importers/          # MoTeC .ld binary decoder, .ldx XML reader, CSV importer, synthetic generator
│   └── moteclib/       # Unified MoTeC importer interface
├── analysis/           # Distance alignment, delta time computation, corner breakdown
├── storage/            # Local SQLite persistence for sessions, laps, and reports
├── coach/              # Local Ollama client and technical driving advisor
├── ui/                 # Streamlit web interface and synchronized Plotly visualizations
├── tests/              # Automated unit and integration test suite
├── Dockerfile          # Reproducible container image with unprivileged appuser
├── compose.yaml        # Docker Compose service with Linux host gateway for Ollama
└── pyproject.toml      # Build metadata and quality tool configurations
```

## 🕹️ Enabling MoTeC Telemetry in ACC (Proton / Steam on Linux)

To record native telemetry files in Assetto Corsa Competizione:

1. Open ACC, select your car (**Porsche 992 GT3 R**) and track (**Valencia**).
2. Go to **Car Setup** > **Electronics** tab.
3. Set **Telemetry Laps** to a positive number (e.g., `99`).
4. Complete your driving stint and return to the pit box. ACC will write the telemetry files.

### File Location on Linux (Steam Proton)
ACC stores MoTeC logs inside its Proton compatibility prefix:
```
~/.local/share/Steam/steamapps/compatdata/805550/pfx/drive_c/users/steamuser/Documents/Assetto Corsa Competizione/MoTeC/
```
In this folder you will find paired `.ld` and `.ldx` files.

## 🚀 Quickstart

### Option A: Local Python Environment (Recommended for Development)

1. **Clone the repository:**
   ```bash
   git clone https://github.com/miquelbar/acc-coach.git
   cd acc-coach
   ```

2. **Create and activate a virtual environment:**
   ```bash
   python3 -m venv .venv
   source .venv/bin/activate
   ```

3. **Install dependencies:**
   ```bash
   pip install -r requirements.txt
   ```

4. **Launch ACC Coach:**
   ```bash
   streamlit run app.py
   ```
   Open your browser at `http://localhost:8501`.

---

### Option B: Docker Compose

1. **Configure Environment:**
   Copy the example environment configuration:
   ```bash
   cp .env.example .env
   ```

2. **Build and Run:**
   ```bash
   docker compose up --build
   ```
   The application will be accessible locally at `http://127.0.0.1:8501`.

> **Note for Linux Host Ollama access:**  
> The `compose.yaml` configuration includes `host.docker.internal:host-gateway` in `extra_hosts`, allowing the containerized app to connect directly to the Ollama service running on your Arch Linux host at `http://host.docker.internal:11434`.

## 🧪 Running Automated Tests

Run the complete test suite with `pytest`:

```bash
source .venv/bin/activate
PYTHONPATH=. pytest -v
```

All 22 unit and integration tests validate binary encoding/decoding, XML lap markers, distance alignment, corner detection, SQLite storage, and Ollama integration.

## 🤖 Ollama Local LLM Setup

To use the AI coach with local GPU acceleration on Linux:

1. Install and start Ollama on your host:
   ```bash
   ollama serve
   ```
2. Pull your preferred model (e.g., Qwen 3 or Qwen 3.8):
   ```bash
   ollama pull qwen3:14b
   ```
   *(Optionally create a custom model with larger context using `.specs/Modelfile_qwen3`: `ollama create qwen3-coach -f .specs/Modelfile_qwen3`)*.
3. In the ACC Coach **Configuración** page, test the connection and select your preferred model. If Ollama is turned off, ACC Coach automatically falls back to its deterministic mathematical rules.
